Website Monitoring

Tracks content changes of a website over time using the Internet Archive's Wayback Machine — combined with a forensic traceroute analysis of the hosting infrastructure.

Wayback Monitoring: Add a URL and click "Live". A chronological list of all saved snapshots is shown, including page size, title changes and direct links to the archived version. The calendar view visualises archiving activity over time. Tags (military, politics, disaster, etc.) help categorise monitored sites.

Traceroute — Server (Live): Click "Server" to run a traceroute to the website's server. Each hop is displayed in real time on a 3D globe (Cesium) with IP address, geographic location, ASN, reverse DNS and round-trip time (RTT). After completion, a forensic enrichment step adds WHOIS data, BGP prefix information and abuse contacts for each hop.

Playback: After the traceroute completes, the slow-motion playback button replays the route on the 3D globe. The animation pauses at each hop proportionally to the measured latency — a hop with 80 ms RTT takes visually twice as long as one with 40 ms. This makes latency bottlenecks and continental crossings immediately visible.

Automatic anomaly detection:
  • RTT jumps: A latency increase of 80+ ms between consecutive hops is flagged (yellow). Jumps of 150+ ms suggest a continental crossing (red).
  • Geographic detours: If the route path is 2.5× longer than the direct distance (and exceeds 800 km), a routing detour is flagged — the traffic may be routed through a third country.
  • Anonymous hop sequences: Two or more consecutive hops that don't respond are flagged. Four or more suggest a closed or military network.
  • BGP anomalies: If a hop's BGP-announced origin AS differs from the observed AS, possible BGP hijacking or anycast is flagged.
  • Plausibility check: The final RTT is compared against the physical minimum (speed of light in fibre ≈ 200,000 km/s). If the measured RTT is faster than physically possible for the distance, CDN or anycast is likely.

Historical Analysis (Parallel Coordinates): After multiple traceroute runs, click "Historical Analysis" to compare them. Each run becomes a line across nine axes: time, total hops, visible hops, anonymous hops, RTT (ms), distance (km), RTT jumps, geographic detours and anonymous sequences. Axes can be dragged to reorder them. Brush (click and drag on an axis) to filter — e.g. select only runs with high RTT to see if they also had more anonymous hops. Grey lines = older runs, purple = most recent. Hover shows details.

What to look for:
  • Sudden changes in hop count or route path between runs → infrastructure change or BGP re-routing
  • RTT increasing over time → degraded connectivity or route change
  • Anonymous hops appearing where there were none before → new filtering or censorship infrastructure
  • Geographic detours through unexpected countries → traffic interception risk
  • Server location mismatch between GeoIP and last traceroute hop → CDN, anycast, or deliberate misrepresentation

Data source: Wayback Machine (Internet Archive) + system traceroute + ip-api.com (GeoIP) + RIPE Stat (BGP/WHOIS) — no API key required.
