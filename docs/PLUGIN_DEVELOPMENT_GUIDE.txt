1. ARCHITECTURE OVERVIEW
============================================================================

spectralQ uses a plugin system with three plugin types:

  watchzone   — Real-time geospatial and web monitoring (vessel, seismic, ...) — 26 plugins
  analysis    — Statistical analysis methods (outlier, forecast, ...) — 11 plugins
  ai          — AI-powered features (trend analysis, telegram analyst, ...) — 10 plugins

  New plugins added in 0.92:
    watchzone/telegram_monitor — Telegram channel/group keyword monitoring
      Features: SearchGlobalRequest, auto-translation, NER geo-extraction,
      channel catalog with 300+ channels, projectized channel management,
      interactive map + calendar, content heatmap, geo/date filtering
    watchzone/commodities — Commodity price monitoring (Yahoo Finance)
      Features: 20 commodities (energy/metals/agri), YoY comparison,
      normalized % charts, time focus support
    watchzone/internet_health — Internet backbone monitoring (IODA API)
      Features: BGP routes, Active Probing, Google Traffic, Unsolicited Traffic,
      submarine cable map (12 sea + 15 terrestrial), cable capacity/RFS data,
      animated cable flow visualization (dot speed/size/color = health),
      timeline playback with slider, anomaly detection (drops + scanning/DDoS spikes),
      pulsing anomaly rings on map, auto-zoom to anomalies,
      concentric distance circles (walking/car/plane),
      distance measurement (D key) with 3-phase cycle,
      chart crosshair with inline data labels, chart playhead sync,
      fullscreen side-by-side layout (map left, charts right),
      focus time event markers on slider + charts,
      analysis triangulation provider with datasource selection,
      collect config (countries, days) + collect renderer (map+cables+animation)
    ai/telegram_analyst — KI analysis of Telegram monitoring data
    ai/internet_health_analyst — KI analysis of connectivity data

  New features in 0.921:
    Global Zone Data Collection ("Sammeln"):
      - "Sammeln" button on global zones collects data from selected plugins
      - Plugin-specific config UI (WZ._collectConfigs) in each plugin's JS
      - Plugin-specific result rendering (WZ._collectRenderers) in each plugin's JS
      - Progress bar during collection, fullscreen results overlay
      - Masonry layout for result cards (column-width: 380px)
      - Overview map with all geo data across plugins
      - Each plugin renders its own card: maps, charts, images, tables

    Distance Measurement (all maps):
      - D key activates measurement on any visible Leaflet map
      - Line + radius circle from start point
      - Travel time calculation: walking (5 km/h), bicycle (20 km/h),
        car (120 km/h), plane (900 km/h, >50km only)

    Internet Health Enhancements:
      - Terrestrial backbone routes (15 routes covering EU, Caucasus, Middle East,
        South/Southeast Asia, East Africa, Afghanistan corridor)
      - Cable hover highlight (red) with wider hit area (15px)
      - Scanning/DDoS spike detection (Merit darknet >50% above mean)
      - Country names in full (ISO→German name mapping)
      - Anomaly table with focus-time highlighting + full-screen list popup
      - Seekabel/Landkabel visibility toggles
      - Relative/Absolute chart mode switch with units (Prefixe, /24-Blöcke, etc.)
      - Click on chart jumps map to that date

    Collect System — Plugin-specific renderers for data collection results:
      internet_health:  Animated cable map + health table
      ndvi:             NDVI images + trend chart with values
      nightlights:      Image + brightness value + focus comparison
      satellite:        True-color image + focus comparison
      seismic:          Map + magnitude table (or "no earthquakes" message)
      weather:          Current values + historical chart (temp/rain) + alerts
      radiation:        Station map + dose rate table
      celltowers:       Map (only with data) + technology breakdown
      acled:            Map + event/fatality table + type breakdown
      powergrid:        Load values + time series chart + anomaly warning
      airquality:       PM2.5 map + station table
      osm_changes:      Map + category/contributor breakdown + change table
      commodities:      Normalized % price chart + focus-time marker + price table
      telegram_monitor: Keyword stats + geo map + timeline chart +
                        chronological messages with translation, split into
                        before/during/after event sections with event marker line,
                        timestamps (date + time)
      aircraft:         Map + callsign/type/altitude/speed table (real-time)
      migration:        Country stats + multi-line chart (refugees/IDPs/asylum)
                        with focus-time marker
      satoverpass:      Witness test + category pie charts (operator/resolution/type)
      website:          Snapshot count + size chart (snapshots/day + KB) + focus marker
      wikipedia:        Per-article edit count + views + chart (edits + views/day) +
                        focus marker

    Collect Configs — Plugin parameter UI for global zone collection:
      internet_health:  Countries (ISO codes), days
      seismic:          Min. magnitude
      weather:          Temperature/precipitation/wind toggles
      commodities:      Commodity selection (checkboxes + custom symbols + import
                        from existing zone), days
      telegram_monitor: Search term + source zone selection (channels import)
      website:          URL (manual or import from existing zone)
      wikipedia:        Articles (manual or import from existing zone)

All plugins:
  - Inherit from a type-specific base class
  - Self-register on import via PluginManager.register()
  - Are auto-discovered at startup from plugins/<type>/<plugin_id>/
  - Can be enabled/disabled per user via the Plugins page

The PluginManager (plugins/__init__.py) handles:
  - Auto-discovery of plugin folders
  - Auto-loading of i18n.json into meta["i18n"]
  - Registration of template directories for Jinja2
  - Per-user enable/disable via AppSetting (opt-out principle)


============================================================================
2. PLUGIN BUNDLE STRUCTURE
============================================================================

Every plugin is a folder inside its type directory:

  plugins/
  └── watchzone/                    # Plugin type
      └── my_sensor/                # Plugin ID = folder name
          ├── __init__.py           # Plugin class (REQUIRED)
          ├── _transport.py         # API fetch functions (data layer)
          ├── _routes.py            # Flask API route handlers (optional)
          ├── i18n.json             # Translations (auto-loaded)
          ├── templates/            # Jinja2 fragments (auto-registered)
          │   └── _panel.html       # Main panel template
          └── static/               # JS/CSS assets (served at runtime)
              └── my_sensor.js      # Frontend renderer

  └── analysis/
      └── my_method/
          ├── __init__.py           # Plugin class + api_routes()
          ├── i18n.json             # Translations (de/en/fr/es)
          └── templates/
              └── _modal.html       # Complete modal (HTML+CSS+JS)

The folder name MUST match the plugin_id defined in the class.

Template paths use the plugin_id as prefix:
  meta["panel_template"] = "my_sensor/_panel.html"
  →  resolves to plugins/watchzone/my_sensor/templates/_panel.html

Static files are served at:
  /plugins/watchzone/my_sensor/static/my_sensor.js
  meta["js_file"] = "/plugins/watchzone/my_sensor/static/my_sensor.js"

3. BUILDING A WATCHZONE PLUGIN
============================================================================

WatchZone plugins provide real-time data for user-drawn geographic zones
or URL-based monitoring zones.

----------------------------------------------------------------------------
3.1 Minimal Example
----------------------------------------------------------------------------

File: plugins/watchzone/my_sensor/__init__.py

  from plugins import PluginManager
  from plugins.watchzone import WatchZonePlugin


  class MySensorPlugin(WatchZonePlugin):
      plugin_id = "my_sensor"

      meta = {
          "label": "My Sensor",
          "icon_svg": '<svg width="18" height="18" viewBox="0 0 24 24" fill="none" '
                      'stroke="currentColor" stroke-width="2">'
                      '<circle cx="12" cy="12" r="10"/></svg>',
          "color": "#10b981",
          "description": "My custom sensor plugin.",
          "category": "geo",              # "geo" | "web" | "search"
          "required_credentials": [],      # e.g. ["my_api_key"]
          "has_live": True,
          "has_history": False,
          "panel_template": "my_sensor/_panel.html",
          "js_file": "/plugins/watchzone/my_sensor/static/my_sensor.js",
      }

      def live_handler(self, zone, config, geo, bbox, user_id):
          # bbox = (min_lon, min_lat, max_lon, max_lat) or None
          if not bbox:
              return {"error": "Zone has no valid geometry"}

          # Fetch your data here
          items = [{"lat": 48.2, "lon": 11.8, "value": 42, "label": "Sensor A"}]

          return {
              "zone_id": zone.id,
              "zone_name": zone.name,
              "zone_type": "my_sensor",
              "count": len(items),
              "items": items,
          }


  PluginManager.register(MySensorPlugin())

That's it. The plugin will appear in the sidebar, be toggleable per user,
and the Live button will call your live_handler().

3.2 Meta Dictionary Reference
----------------------------------------------------------------------------

  REQUIRED KEYS:
    label                   Display name in sidebar and plugin list
    icon_svg                Inline SVG string (18x18)
    color                   Hex color for sidebar icon and zone outlines
    description             Short description for plugin management page
    category                "geo" (map-based), "web" (URL-based), "search"
    has_live                True if plugin supports live data fetching
    has_history             True if plugin provides time series for analysis
    panel_template          Jinja2 template path: "<plugin_id>/_panel.html"
    js_file                 Static JS path: "/plugins/watchzone/<id>/static/<id>.js"

  OPTIONAL KEYS:
    required_credentials    List of AppSetting keys needed (e.g. ["my_api_key"])
    apa_action              APA action name (e.g. "vessel_traffic", "seismic_history")
                            Enables dynamic dispatch from apa_stream.py
    overlay_template        Extra modal template
    live_header_template    Buttons injected into live popup header
    live_side_panels_template  Side panels next to live map
    live_map_inset_template    Elements inside the live map
    live_undermap_template     Buttons below the live map

  INHERITED (from BasePlugin, usually auto-loaded from i18n.json):
    i18n                    {de: {...}, en: {...}, fr: {...}, es: {...}}

----------------------------------------------------------------------------
3.3 live_handler(zone, config, geo, bbox, user_id)
----------------------------------------------------------------------------

Called when user clicks "Live" on a zone.

  Arguments:
    zone        WatchZone SQLAlchemy model instance
                  zone.id, zone.name, zone.zone_type, zone.geometry, zone.config
    config      dict — parsed zone.config JSON (user-defined settings)
    geo         dict — parsed zone.geometry GeoJSON
    bbox        tuple (min_lon, min_lat, max_lon, max_lat) or None
    user_id     int

  Must return:
    dict — will be JSON-serialized and passed to your JS renderer

  Convention:
    {
      "zone_id": int,
      "zone_name": str,
      "zone_type": "my_sensor",   # must match plugin_id
      "count": int,
      "items": [...]              # your data
    }

  On error:
    {"error": "Human-readable message"}

----------------------------------------------------------------------------
3.4 history_routes()
----------------------------------------------------------------------------

Define additional API endpoints for historical data (used in analysis
triangulation).

  Returns:
    list of {"suffix": str, "handler": callable}

  The handler receives (zone, args, user_id):
    zone    WatchZone model instance
    args    request.args (ImmutableMultiDict)
    user_id int

  The route is auto-registered as:
    GET /api/watchzones/<int:zid>/<suffix>

  Example:

    def history_routes(self):
        return [{"suffix": "my-sensor-history", "handler": self._history}]

    def _history(self, zone, args, user_id):
        from flask import jsonify
        date_from = args.get("from", "")
        date_to = args.get("to", "")
        # fetch historical data...
        return jsonify({"zone_id": zone.id, "data": [...]})

----------------------------------------------------------------------------
3.5 api_routes() — Standalone API Endpoints
----------------------------------------------------------------------------

Define standalone API endpoints that are not zone-specific.
These are auto-registered at startup via _register_wz_api_routes().

  Returns:
    list of {"rule": str, "handler": callable, "methods": [str]}

  The handler is wrapped with @login_required automatically.

  Example:

    def api_routes(self):
        from plugins.watchzone.my_sensor._routes import api_sensor_data
        return [{"rule": "/api/my-sensor/data", "handler": api_sensor_data}]

  The route handler goes in _routes.py:

    # plugins/watchzone/my_sensor/_routes.py
    from flask import request, jsonify

    def api_sensor_data():
        from flask_login import current_user
        # ... your endpoint logic
        return jsonify({"data": [...]})

  The _transport.py pattern:
    Put API fetch logic (HTTP calls to external services) in _transport.py.
    Route handlers in _routes.py import from _transport.py.
    This keeps data access separate from Flask request handling.

3.6 ai_tools() and ai_tool_handler()
----------------------------------------------------------------------------

Expose your plugin's data to the AI Project Assistant (APA).

  ai_tools() returns a list of Anthropic-format tool definitions:

    def ai_tools(self):
        return [{
            "name": "my_sensor_data",
            "description": "Fetches sensor data for a region.",
            "input_schema": {
                "type": "object",
                "properties": {
                    "zone_id": {"type": "integer"},
                    "bbox": {"type": "array", "items": {"type": "number"}},
                },
            },
        }]

  ai_tool_handler(tool_name, inputs, user_id) executes the tool call:

    def ai_tool_handler(self, tool_name, inputs, user_id):
        if tool_name != "my_sensor_data":
            return {"error": f"Unknown tool: {tool_name}"}
        # resolve bbox, fetch data, return dict
        return {"count": 5, "data": [...]}

The APA will automatically discover and use these tools in conversations.

----------------------------------------------------------------------------
3.7 analysis_provider()
----------------------------------------------------------------------------

Enable your plugin's data as a triangulation source in the analysis view.

    def analysis_provider(self):
        return {
            "data_types": ["my_sensor"],
            "history_endpoint_suffix": "my-sensor-history",
        }

  Returns None (default) if no analysis integration needed.

  "data_types" controls which checkboxes appear in the triangulation panel.
  "history_endpoint_suffix" must match a suffix from history_routes().

3.8 apa_action_handler(action)
----------------------------------------------------------------------------

Handle APA (AI Project Assistant) actions for this plugin. When the APA
coordinator issues an action matching your meta["apa_action"], this handler
is called automatically via dynamic dispatch in apa_stream.py.

  Prerequisites:
    Set meta["apa_action"] to your action name (e.g. "vessel_traffic").

  Arguments:
    action      dict — action parameters from APA coordinator
                  Typical keys: bbox, days, label, zone_id, url, etc.

  Must return:
    Success: {
      "status_msg": "Human-readable status during execution",
      "report":     "Multi-line detailed report for researcher_reports",
      "data_msg":   "Short summary for SSE data event",
      "error":      None,
    }
    Error: {"error": "Human-readable error message"}

  Example:

    meta = {
        ...
        "apa_action": "my_sensor_history",
    }

    def apa_action_handler(self, action):
        from plugins.watchzone.my_sensor._transport import fetch_history
        bbox = action.get("bbox", [])
        days = min(action.get("days", 180), 730)
        label = action.get("label", "Region")
        if len(bbox) != 4:
            return {"error": "bbox muss 4 Werte haben"}
        data = fetch_history(bbox, days)
        if not data:
            return {"error": f"{label}: Keine Daten"}
        return {
            "status_msg": f"Sensor-Daten: {label} ({days}d) …",
            "report": f"SENSOR ({label}): {len(data)} Messwerte",
            "data_msg": f"Sensor {label}: {len(data)} Messwerte",
            "error": None,
        }

  The dispatch in apa_stream.py builds a lookup map from all plugins
  with meta["apa_action"] set. No code changes in apa_stream.py needed.

3.10 JavaScript (Live Renderer)
----------------------------------------------------------------------------

File: plugins/watchzone/my_sensor/static/my_sensor.js

  (function() {
  "use strict";
  var WZ = window.WZ;

  function _renderLive(data) {
    var items = data.items || [];

    // Update the live popup count
    document.getElementById("wz-live-count").textContent =
      items.length + " readings";

    // Clear existing map markers
    if (WZ._liveMarkers) WZ._liveMarkers.clearLayers();

    // Render content in live popup
    var content = document.getElementById("wz-live-content");
    if (!items.length) {
      content.innerHTML = '<p style="text-align:center;color:var(--muted);">No data.</p>';
      return;
    }

    // Add markers to map
    items.forEach(function(item) {
      var m = L.marker([item.lat, item.lon]);
      if (WZ._liveMarkers) WZ._liveMarkers.addLayer(m);
    });

    // Fit map to markers
    if (WZ._liveMap && WZ._liveMarkers && WZ._liveMarkers.getLayers().length) {
      WZ._liveMap.fitBounds(WZ._liveMarkers.getBounds(), {padding: [30,30]});
    }

    // Render table/list
    content.innerHTML = '<table>...</table>';
  }

  WZ.registerPlugin("my_sensor", {
    renderer: _renderLive,
    // Optional capabilities:
    has_map: true,           // false for URL-based plugins (website, wayback)
    has_live_map: true,      // show map in live popup
    has_heatmap: false,      // enable heatmap toggle button
    has_refresh_bar: false,  // show auto-refresh bar
    default_source: null,    // default source for new zones
  });

  })();

  KEY GLOBALS:
    WZ._liveMarkers   — L.LayerGroup for live popup map markers
    WZ._liveMap        — L.Map instance in live popup
    WZ._esc(str)       — HTML-escape helper
    WZ._anomalyBadge(score) — colored score badge HTML
    window._t(key, fallback) — i18n translation function

3.12 Collect Config (Global Zone Data Collection)
----------------------------------------------------------------------------

When a global zone collects data from multiple plugins ("Sammeln"), each
plugin can provide a configuration UI. Register in your plugin's JS file:

  WZ._collectConfigs["my_sensor"] = {
    fields: function(saved) {
      // saved = previously stored config values (or {})
      // Return HTML string with form elements.
      // Use class="wz-cc-field" + data-key="fieldname" for auto-reading.
      return '<label>Min. Threshold</label>'
        + '<input class="wz-cc-field" data-key="threshold" value="' + (saved.threshold || 10) + '">';
    },
    read: function(container) {
      // Read values from the config panel DOM container.
      // Return a plain object that will be saved to zone.config.plugins[pluginId].
      var inp = container.querySelector('[data-key="threshold"]');
      return { threshold: parseFloat(inp.value) || 10 };
    }
  };

The config is stored in zone.config.plugins.<pluginId> via PUT /api/watchzones/<id>.
On collection, the backend merges these values into the config passed to live_handler().

To import settings from existing zones of the same type:

  var h = '<select class="wz-cc-field" data-key="_import" onchange="...">';
  (WZ._zones || []).forEach(function(z) {
    if (z.zone_type !== "my_sensor") return;
    h += '<option value="' + z.id + '">' + WZ._esc(z.name) + '</option>';
  });

When a user interacts with the config panel, the plugin's checkbox is
automatically checked (input/change events are monitored by the framework).

3.13 Collect Renderer (Global Zone Result Display)
----------------------------------------------------------------------------

After data collection, each plugin can provide custom result rendering.
Register in your plugin's JS file:

  WZ._collectRenderers["my_sensor"] = {
    renderHTML: function(data, cardId, zone) {
      // data = response from live_handler()
      // cardId = unique DOM ID prefix for this card
      // Return HTML string for the card body (header is rendered by framework).
      var h = '';
      if (data.items && data.items.length) {
        h += '<div id="' + cardId + '-map" style="height:400px;border-radius:6px;margin-bottom:8px;"></div>';
        h += '<table>...</table>';
      }
      return h;
    },
    afterRender: function(data, cardId, cardEl) {
      // Called after HTML is in the DOM. Initialize maps, charts, animations.
      // cardEl = the card's DOM element
      if (!window.L) return;
      var mapEl = cardEl.querySelector("[id$='-map']");
      if (!mapEl) return;
      var m = L.map(mapEl, { zoomControl: false }).setView([48, 10], 5);
      L.tileLayer("https://{s}.basemaps.cartocdn.com/dark_nolabels/{z}/{x}/{y}{r}.png").addTo(m);
      // Add markers, bindings, etc.
    }
  };

If no renderer is registered, the generic fallback is used:
  - WZ._collectGenericHTML(data, cardId) — images, tables, geo map placeholder
  - WZ._collectGenericAfterRender(r, cardId, cardEl) — Leaflet map init

Helpers available to renderers:
  - WZ._esc(str)          HTML-escape a string
  - WZ._fmtDate(str)      Format date using admin-configured format
  - WZ.ZONE_COLORS[pid]   Plugin accent color
  - WZ.PLUGIN_LABELS[pid] Localized plugin name

Focus Time annotation example (for Chart.js plugins):

4. BUILDING AN ANALYSIS PLUGIN
============================================================================

Analysis plugins provide statistical methods that operate on keyword
time series data. They appear in the analysis popup and/or the lab.

----------------------------------------------------------------------------
4.1 Minimal Example
----------------------------------------------------------------------------

File: plugins/analysis/my_method/__init__.py

  from plugins import PluginManager
  from plugins.analysis import AnalysisPlugin


  class MyMethodPlugin(AnalysisPlugin):
      plugin_id = "my_method"

      meta = {
          "label": "My Method",
          "icon_svg": '<svg viewBox="0 0 24 24" width="18" height="18" .../>',
          "color": "#f59e0b",
          "symbol": "M",
          "description": "Custom statistical analysis.",
          "default_show_in": ["popup"],     # "lab", "popup", or both
          "button_id": "btn-my-method",
          "requires_multi_kw": False,       # True = needs >= 2 keywords
          "popup_handler": "openMyMethodForKw",
          "popup_badges": [["my_method_badge", "Result"]],
      }

      def api_routes(self):
          return [{
              "rule": "/api/my-method",
              "handler": self._handle,
              "methods": ["POST"],
          }]

      def compute(self, body):
          from plugins.analysis._helpers import load_series

          labels, series = load_series(body)
          if not series:
              return {"error": "No data", "_status": 400}

          s = series[0]
          values = [v for v in s["values"] if v is not None]
          if not values:
              return {"error": "No non-null values", "_status": 400}

          # Your analysis logic here
          mean = sum(values) / len(values)

          return {
              "keyword": s["keyword"],
              "mean": round(mean, 2),
              "count": len(values),
              "summary": f"Mean value: {mean:.1f} over {len(values)} data points.",
          }

      def _handle(self):
          from flask import request, jsonify
          body = request.get_json(force=True, silent=True) or {}
          result = self.compute(body)
          status = result.pop("_status", 200)
          return jsonify(result), status


  PluginManager.register(MyMethodPlugin())

----------------------------------------------------------------------------
4.3 compute(body)
----------------------------------------------------------------------------

The core computation function. Receives the request body as dict.

  Input (body):
    From database:
      {"keyword_ids": [1, 2, 3]}
      {"keyword_ids": [1], "run_tag": "latest"}

    From JSON (e.g. APA calling directly):
      {"data": [{"keyword": "test", "values": [10, 20, ...], "dates": ["2024-01-01", ...]}]}

  Use load_series(body) to normalize both input formats:
    from plugins.analysis._helpers import load_series
    labels, series = load_series(body)
    # labels = ["2024-01-01", "2024-01-02", ...]
    # series = [{"keyword": "test", "values": [10, 20, ...], "kwId": 1}, ...]

  Return:
    Success: {"keyword": "...", "result": ..., "summary": "..."}
    Error:   {"error": "message", "_status": 400}

  The "_status" key is popped by the handler and used as HTTP status code.

----------------------------------------------------------------------------
4.4 api_routes()
----------------------------------------------------------------------------

Define HTTP endpoints for your analysis method.

  Returns: list of {"rule": str, "endpoint": str, "handler": callable, "methods": [str]}

  The handler is wrapped with @login_required automatically.
  The "endpoint" key provides an explicit Flask endpoint name (used for
  unique route registration: an_<plugin_id>_<endpoint>).
  Convention: POST to /api/<method-name>

  Standard handler pattern:

    def _handle(self):
        from flask import request, jsonify
        body = request.get_json(force=True, silent=True) or {}
        result = self.compute(body)
        status = result.pop("_status", 200)
        return jsonify(result), status

7. CREDENTIAL SYSTEM
============================================================================

If your plugin requires API keys:

  1. List them in meta["required_credentials"]:
     "required_credentials": ["my_service_api_key"]

  2. The plugin will show a credential input on the /plugins page
  3. Users enter their key → stored in AppSetting per user
  4. is_available(user_id) automatically checks:
     a) User-specific AppSetting
     b) Global AppSetting (admin-configured)
     c) Environment variable (MY_SERVICE_API_KEY)
  5. If no key found → plugin shows as "unavailable"

  To read the credential in your code:
    from models import AppSetting
    key_obj = AppSetting.query.filter_by(key="my_service_api_key", user_id=user_id).first()
    api_key = key_obj.value if key_obj else ""

8. NON-GEO PLUGINS (No Map)
============================================================================

  Plugins without a map (has_map: false) need special handling:

  FULL-WIDTH LIVE POPUP:
    In your JS renderer, add:
      var lb = document.getElementById("wz-live-box");
      if (lb) lb.classList.add("wz-live-fullwidth");
      var _body = document.getElementById("wz-live-body");
      if (_body) _body.style.display = "block";

    The CSS class is defined in events_watchzones.html:
      #wz-live-box.wz-live-fullwidth { max-width: 98vw !important; width: 96% !important; }

    The display:block fix prevents flex shrinking of wz-live-content.

  HIDING CORE MAP:
    In your renderer, hide the core map row:
      var _mapRow = document.getElementById("wz-map-row");
      if (_mapRow) _mapRow.style.display = "none";

  CUSTOM EDIT HANDLER:
    Override wzEditZone for your zone_type:
      var _origEdit = window.wzEditZone;
      window.wzEditZone = function(id, panel) {
        if (panel === "my_plugin") { _myEditZone(id); return; }
        if (_origEdit) _origEdit(id, panel);
      };

  DATA CACHING (24h):
    Use the shared cache from telegram_monitor:
      from plugins.watchzone.telegram_monitor._cache import get as cache_get, put as cache_put
      cached = cache_get(zone.id, config)
      if cached: return cached
      # ... fetch data ...
      cache_put(zone.id, config, result)

  PROJECTIZED ZONES:
    Pass project_id when creating zones:
      var _projSel = document.getElementById('hdr-wz-project');
      var _projectId = _projSel && _projSel.value ? parseInt(_projSel.value) : null;

  TIME FOCUS:
    Read from own zone config (not inherited):
      import json as _j2
      _own_config = _j2.loads(zone.config) if zone.config else {}
      tf = _own_config.get("time_focus")

  REGISTER PLUGIN:
    WZ.registerPlugin("my_plugin", {
      renderer: _myRenderer,
      has_map: false,
      has_live_map: false,
      live_box_max_width: "98vw",
      live_title_prefix: "My Plugin",
    });
